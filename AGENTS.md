# AGENTS.md — AzerothCore

## Build

- Out-of-source build **required** (enforced by CMake).
- Use `acore.sh compiler all` for clean+configure+compile, or call CMake directly.
- CMake options: `SCRIPTS` (static/dynamic/minimal), `MODULES` (static/dynamic), `APPS_BUILD` (all/auth-only/world-only), `TOOLS_BUILD` (none/all/db-only/maps-only).
- CI builds with `-Werror`. Use `-DCMAKE_CXX_FLAGS="-Werror"` locally to match.
- Bash build system reads overrides from `conf/config.sh` (not `conf/config.cmake`).
- Modules live in `modules/` dir, each with its own `CMakeLists.txt`. Disable via `-DDISABLED_AC_MODULES="mod1;mod2"`.

## Script Registration (frequent footgun)

Scripts are **not** auto-discovered. Each must be registered:
1. Define a class inheriting from `SpellScript`, `CreatureScript`, etc.
2. Implement `AddSC_*()` calling `RegisterSpellScript(ClassName)` (or similar).
3. Add the `AddSC_*()` call to the regional `*_script_loader.cpp`.
4. Regional loaders per dir: `EasternKingdoms`, `Kalimdor`, `Northrend`, `Outland`, `Spells`, `Commands`, `Events`, `Custom`, `World`.
5. Spell scripts go in `Spells/spell_<class>.cpp`.

The `ScriptLoader.cpp` is auto-generated by CMake from `ScriptLoader.cpp.in.cmake` — do not edit it manually.

## Database

- Three databases: `acore_auth` (accounts), `acore_characters` (characters), `acore_world` (game content).
- SQL updates go in `data/sql/updates/pending_<db>/` before merge. **Never modify files outside `pending_*` folders.**
- SQL conventions: backticks on identifiers, single quotes for strings, `DELETE` before `INSERT` (never `REPLACE`), snake_case tables, UpperCamelCase columns, `INT` not `INT(11)`.

## Code Style (non-obvious)

- `const` **after** type: `Player const* player` (not `const Player*`).
- Private members: `_lowerCamelCase` prefix (`_someGuid`). Public/protected: `UpperCamelCase`.
- No `m_` prefix. No `p` pointer prefix.
- Float literals always have `f` suffix: `1.0f`.
- Format output with `{}` placeholders, **not** printf-style (`%u`, `%s`).
- Standard prefixes for constants: `SPELL_`, `NPC_`, `ITEM_`, `GO_`, `QUEST_`, `EVENT_`, `DATA_`, `ACHIEV_`.
- Max 80 chars, 4-space indentation (C++), 2-space (JSON/YAML/shell), LF line endings, no trailing whitespace.

## Testing

- Google Test, source in `src/test/`.
- Binary: `build/src/test/unit_tests`. Enable via `-DBUILD_TESTING=ON`.
- Integration/dry-run tests require MySQL running and DBC files (`ac-data`).

## PR Requirements

- AI tool usage **must be disclosed** in PR description.
- In-game testing expected and documented.
- Generic code changes require regression testing of related systems.
- Commits use Conventional Commits: `Type(Scope/Subscope): short desc` — types: feat/fix/refactor/style/docs/test/chore, scopes: Core/DB.

## Two-server architecture

- **authserver** (`src/server/apps/authserver/`): port 3724, handles auth & realm list.
- **worldserver** (`src/server/apps/worldserver/`): port 8085, all gameplay.
- Shared code in `src/server/shared/`, game logic in `src/server/game/` (~52 subsystems).
